# Зошит — спільна бібліотека знань

Учні читають матеріали без входу та можуть запропонувати власний конспект. Адміністратор перевіряє пропозиції й додає схвалені до спільної бібліотеки: предмет → тема → параграф.

## Як працюють пропозиції

1. Натисни **Запропонувати конспект** і увійди за посиланням, надісланим на пошту.
2. Вкажи предмет, тему, назву й текст конспекту. Нові предмети й теми можна вписати у форму. За бажанням додай стиснуте зображення до 500 КБ.
3. Надісланий матеріал бачить автор і адміністратор. Він з’явиться для всіх лише після схвалення.
4. Адміністратор відкриває **Пропозиції**, читає конспект і натискає **Опублікувати** або **Відхилити**.

Сервер обмежує кількість пропозицій до 10 на годину з одного облікового запису. Перевірка прав і публікація виконуються в Supabase, а не лише кнопками на сайті.

## Зручності для повторення

- Обране, нещодавно відкриті матеріали й позначка прочитаного зберігаються у браузері на цьому пристрої.
- Особисті нотатки до параграфа також залишаються тільки в цьому браузері й не потрапляють у спільну бібліотеку.
- Адміністратор може додати до параграфа теги; пошук знаходить збіги в назвах, тексті та тегах.
- Зміни параграфів зберігаються в історії версій (до 8 попередніх станів).
- Учні можуть увійти й повідомити про помилку; адміністратор переглядає повідомлення в черзі та позначає вирішені. Перевиконати `supabase/submissions.sql`, щоб створити таблицю повідомлень.
- Кнопка **Друк / PDF** відкриває системне вікно друку, де можна зберегти матеріал як PDF.
- Адміністратор може масово додавати матеріали через CSV. Скачай приклад у вікні імпорту. Обов’язкові стовпці: `предмет`, `тема`, `назва`; додаткові: `опис`, `конспект`, `теги`. Кілька тегів розділяй символом `|`.

## Налаштування Supabase

GitHub Pages розміщує сайт, а Supabase зберігає спільну бібліотеку та чергу пропозицій.

1. У Supabase **SQL Editor** виконай `supabase/schema.sql`.
2. Відкрий файл `supabase-config.js` і вкажи Project URL та publishable/anon key. Не додавай `secret` або `service_role` key до сайту.
3. У **Authentication → URL Configuration** додай адресу опублікованого сайту до дозволених redirect URLs.
4. Опублікуй файли через `Опублікувати_сайт.bat`.
5. Увійди на сайті власною поштою. У Supabase **Authentication → Users** скопіюй UUID цього облікового запису.
6. Додай себе в `library_admins`, виконавши в SQL Editor запит нижче з власним UUID:

```sql
insert into public.library_admins (user_id)
values ('00000000-0000-0000-0000-000000000000');
```

7. Виконай `supabase/submissions.sql`, щоб увімкнути чергу пропозицій і модерацію.

Якщо локальні матеріали вже є в браузері адміністратора, перенеси їх у спільну бібліотеку до того, як учні почнуть надсилати пропозиції.

## Імпорт Google Classroom (лише для адміністратора)

Імпорт доступний лише обліковому запису з `library_admins`. Він читає активні класи, теми та навчальні матеріали Classroom, показує попередній перегляд і після підтвердження додає їх до спільної бібліотеки: клас → предмет, тема Classroom → тема, матеріал → параграф. Додані Google Drive-файли лишаються посиланнями на оригінали. Повторний імпорт не дублює вже додані матеріали.

Щоб увімкнути:

1. У [Google Cloud Console](https://console.cloud.google.com/) створи або вибери проєкт і ввімкни **Google Classroom API**.
2. Налаштуй OAuth consent screen. Для OAuth Client ID створи облікові дані типу **Web application**.
3. Додай `https://uyli228.github.io` у **Authorized JavaScript origins**.
4. Скопіюй OAuth Client ID у поле `classroomClientId` файлу `supabase-config.js`, збережи й опублікуй сайт.
5. На сайті ввійди обліковим записом адміністратора, натисни **Імпорт Classroom**, під’єднай Google, вибери класи та переглянь розподіл перед додаванням.

Додавай лише Client ID (публічний ідентифікатор). Не вставляй у сайт client secret і не надсилай пароль Google. Під час під’єднання сайт запитує тільки дозволи читання курсів, тем і course work materials; вміст Classroom не змінюється. Для тестування Google може вимагати додати свій акаунт до списку test users. Імпорт зараз бере саме навчальні матеріали Classroom, а не завдання та відповіді учнів.

## Публікація сайту

Двічі клацни `Опублікувати_сайт.bat`. Потрібні Git for Windows, GitHub CLI та вхід у свій GitHub-акаунт. Скрипт збереже зміни, відправить їх у репозиторій і дочекається публікації GitHub Pages.
